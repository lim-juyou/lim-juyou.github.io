    插入排序

    插入排序的流程如下（以升序为例）：

    初始状态：将数组首个元素视为已排序序列。
    逐个插入：
    从第二个元素开始，依次与已排序序列中的元素从后往前比较。
    若当前元素 < 已排序元素，则将已排序元素后移一位。
    找到合适位置后，插入当前元素。
    重复操作：直到所有元素被插入到正确位置。

    算法 稳定性 时间复杂度（均） 适用场景
    插入排序 ✔️ O(n²) 小规模/近乎有序数据
    选择排序 ❌ O(n²) 简单但性能无优势
    冒泡排序 ✔️ O(n²) 教学示例，实际少用
    快速排序 ❌ O(n log n) 大规模通用排序

    递归实现(时间复杂度O(logn),空间复杂度（O(logn))

    (2)

    1. 初始化：左边界 left = 0，右边界 right = nums.length - 1，结果初始化为 nums.length（若未找到则返回该值）。
    2. 循环缩小范围：
      • 计算中间位置 mid = left + (right - left) / 2（避免整数溢出）。
      • 若 nums[mid] ≥ target：记录候选位置 result = mid，并继续向左查找（缩小右边界：right = mid - 1）。
      • 若 nums[mid] < target：调整左边界为 mid + 1，继续向右查找。
    3. 结束条件：当 left > right 时终止循环，返回 result。

    💡 关键点

    • 记录候选位置：当中间元素满足条件时，更新结果并探索左侧是否有更小的索引。
    • 最终结果处理：
      • 若 result < nums.length，返回该位置（找到）。
      • 若未找到（result 保持初始值 nums.length），可返回 -1 表示无解（根据需求调整）。

    先判断0位置和最后一个位置上是否为局部最小值，如果是，直接返回。如果不是，那么从0位置到1是向下递减的，而从n-1到n是向上递增的，所以中间一定存在拐点，及局部最小值。此时也可以用二分，取中点位置，如果其大于左右两侧相邻的数，直接返回mid, 如果左侧大于mid，那mid - 1到mid + 1是递减，说明在mid + 1 到right存在局部最小，同理如果右侧大于mid,那么left 到 mid - 1存在局部最小。

    比较器

    比较器的实质就是重载比较运算符

    比较器可以很好的应用在特殊标准的排序上

    比较器可以很好的应用在根据特殊标准排序的结构上

    在 Java 中，比较器用于定义对象的排序规则，主要通过 Comparable 和 Comparator 两个接口实现。以下是详细解释、应用场景和代码示例：

    一、比较器的核心概念

    1. Comparable 接口

    • 作用：定义对象的自然排序规则（默认排序方式）。
    • 方法：compareTo(T o)，返回 int 值：
      • 正数：当前对象 > 参数对象
      • 负数：当前对象 < 参数对象
      • 零：当前对象 = 参数对象
    • 特点：需要修改对象类，实现排序逻辑。

    2. Comparator 接口

    • 作用：定义灵活的自定义排序规则（无需修改对象类）。
    • 方法：compare(T o1, T o2)，返回 int 值（规则同上）。
    • 特点：支持多种排序规则，可通过匿名类、Lambda 或方法引用实现。

    二、应用场景

    1. 集合排序：对 List、Set、数组进行排序。
    2. 有序数据结构：TreeSet、TreeMap 等依赖排序的数据结构。
    3. 多条件排序：按不同字段（如年龄、姓名）灵活排序。
    4. 第三方类排序：无法修改类源码时，通过 Comparator 定义规则。
    5. Java 8 Stream 操作：在流处理中排序数据。

    java库提供的内置函数Arrays.sort()，如果提供的是基本数值类型系统会使用快排，如果是自定义的类型会使用归并排序。

    Java中的Arrays.sort()方法在不同数据类型下采用不同排序算法的策略，其背后的关键考量在于 稳定性需求 与 性能优化 之间的权衡。以下是具体分析：

    1. 基本数据类型（如int[], double[]等）采用双轴快速排序（Dual-Pivot Quicksort）
      原因：无需稳定性

    基本数据类型（如int）的排序不需要保证相同值的元素在排序后的相对顺序与原数组一致。例如：

    int[] arr = {3, 1, 3}; Arrays.sort(arr); // 结果可能是[1, 3, 3]，两个3的相对顺序无意义 性能优势

    双轴快速排序是原地排序（基本无需额外空间），平均时间复杂度为

    在处理链表中点问题时，快慢指针法通过调整快指针的终止条件，可以精确控制慢指针的停止位置。以下是不同场景的具体实现策略：

    场景一：快慢指针初始化为 head

    终止条件：fast != null && fast.next != null

    • 奇数长度

      • slow 停在正中间节点
      • 示例：链表 1→2→3→4→5 ⇒ slow 停在 3

    • 偶数长度

      • slow 停在第二个中间节点
      • 示例：链表 1→2→3→4 ⇒ slow 停在 3

    场景二：偶数长度时慢指向前一个中间节点

    调整条件：fast.next != null && fast.next.next != null

    • 奇数长度

      • slow 停在正中间节点
      • 示例：链表 1→2→3 ⇒ slow 停在 2

    • 偶数长度

      • slow 停在第一个中间节点
      • 示例：链表 1→2→3→4 ⇒ slow 停在 2

    符号总结

    场景 终止条件 奇/偶 slow 停止位置
    初始条件，默认情况 fast != null && fast.next != null 奇数 中间节点
    偶数 第二个中间节点
    精确控制偶数为前一个中间节点 fast.next != null && fast.next.next != null 奇数 中间节点
    偶数 第一个中间节点

    关键设计原理

    1. 快指针的遍历边界：
      当 fast 的终止条件允许走两步时：

      • fast.next != null：允许访问无 NullPointerException
      • fast.next.next != null：严格限制快指针仅在偶数长度下提前终止

    2. 初始化位置：

      • 若两者均从 head 开始，默认会偏向偶数长度的第二个中间节点
      • 若 fast = head.next：可直接让慢指针在偶数长度时偏向第一个中间节点

    扩展：强制慢指针停在中间前一个节点

    此时无论奇偶，slow 始终指向中间节点的前驱节点。

    通过灵活调整快慢指针的起始位置和终止条件，可以精准控制慢指针的中段定位，从而适应不同场景需求。

    二叉树动态规划（DP）问题的常见套路

    二叉树中的动态规划问题通常结合树的结构与递归特性，通过状态转移和记忆化优化来解决。以下是核心套路的详细拆解及应用示例：

    💡 核心思路

    将树的结构分解为 子问题，利用递归的天然分治特性，传递状态并合并子树结果。关键在于找到：

    1. 递归的结构：如何定义每个节点的状态和子问题
    2. 状态转移方程：如何用子节点的状态推导父节点状态
    3. 结果合并方式：如何将子树计算结果组合为全局最优解

    🛠 四大核心解题步骤

    1. 定义状态
    为每个节点设计需要记录的 状态变量（通常以返回值形式存在）。例：

    • 节点作为根时的最大路径和
    • 节点左子树最大深度
    • 是否以该节点为根的子树是二叉搜索树

    2. 状态转移方程
    根据子节点的状态推导当前节点的状态。例：

    3. 递归终止条件
    处理空节点或叶子节点的情况，初始化边界值。例：

    • 空节点返回 0（如路径和问题）
    • 叶子节点返回 1（如计算深度问题）

    4. 合并全局最优解
    在递归过程中维护全局变量（如最大路径和、最长直径等），通过各节点的状态计算结果更新全局答案。

    🌰 典型题型与解析

    1. 二叉树最大路径和（LeetCode 124）

    关键点：

    • 状态变量：每个节点的单侧（向左或右延伸）最大贡献值
    • 转移方程：单侧贡献 = max(左贡献, 右贡献) + 当前值
    • 全局更新：包含当前节点的完整路径（左→当前→右）需单独处理

    2. 二叉树直径（LeetCode 543）

    关键点：

    • 状态变量：当前节点为根的子树的最大深度
    • 转移方程：深度 = max(左深度, 右深度) + 1
    • 全局更新：路径长度为左深度 + 右深度

    🔄 模版通用代码结构

    📌 常见题型特征

    出现以下特征时，优先考虑二叉树 DP 套路：

    • 题目要求计算 全局最优解（如最大值、最长路径）
    • 每个节点的解依赖其 左右子树的解
    • 需要合并子树计算结果（例如路径问题、距离问题）
    • 可能需要 剪枝或筛选 递归路径（如平衡二叉树验证）

    ⚠️ 重点关注

    • 状态变量的设计：选择适合合并的信息作为递归返回值
    • 全局变量的维护：确保递归过程中能正确更新最优解
    • 剪枝优化：例如在平衡二叉树判断中，发现子树不平衡时立即中断递归
    • 负数贡献处理：路径和问题中若子节点贡献为负，应舍弃（如 max(0, …)）

    通过掌握这些核心思路和模版，可以高效解决大部分二叉树 DP 问题！
