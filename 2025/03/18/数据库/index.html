2.数据类型

数值类型

  • 整数：INT, SMALLINT, TINYINT, BIGINT（不同范围）
  • 浮点数：FLOAT, DOUBLE, DECIMAL（精确小数，如货币）

字符类型

固定长度：CHAR(n)（定长，填充空格）
可变长度：VARCHAR(n)（变长，按实际长度存储）
长文本：TEXT（大段文本，如文章）

日期时间类型

DATE（年月日）
TIME（时分秒）
DATETIME或TIMESTAMP（日期+时间）

二进制类型

  • BINARY（定长二进制）
  • VARBINARY（变长二进制）
  • BLOB（大二进制文件，如图片）

其他类型

  • BOOLEAN（逻辑值）
  • JSON（结构化JSON数据）
  • XML（XML格式）

CHAR vs. VARCHAR 的区别

特性 CHAR VARCHAR
存储方式 定长（固定分配空间） 变长（按需分配）
空格填充 不足长度时填充空格 不填充，保持原数据
存储开销 固定为定义的长度（可能浪费空间） 实际长度 + 1~2字节（记录长度信息）
适用场景 固定长度数据（如国家代码、MD5） 长度变化大的数据（如用户名、地址）
性能 检索更快（长度固定，利于索引） 存储更高效（但频繁更新可能更慢）
比较行为 比较时可能忽略尾部空格（因填充） 严格按存储值比较（包括尾部空格）

语法1：

两者之间的区别:

  1. 定义与语法
操作 语法 是否支持WHERE条件
DELETE DELETE FROM 表名 [WHERE ...] 支持
TRUNCATE TRUNCATE TABLE 表名 不支持
  1. 核心区别
特性 DELETE TRUNCATE
机制 逐行删除记录，记录事务日志。 直接释放数据页（删除表数据文件），日志记录最少。
性能 较慢（逐行删除，日志量大）。 更快（批量操作，日志精简）。
事务与回滚 DML操作，支持事务回滚（需显式提交）。 DDL操作，某些数据库隐式提交事务（无法回滚，取决于具体实现，如Oracle；在MySQL的InnoDB中可回滚）。
触发器 触发BEFORE DELETE和AFTER DELETE触发器。 不触发触发器。
自增列重置 不重置自增列的起始值。 重置自增列的起始值（如MySQL的AUTO_INCREMENT重置为1）。
外键约束处理 逐行检查外键约束（若有ON DELETE规则则触发级联操作）。 若表被外键引用，某些数据库（如MySQL）禁止直接TRUNCATE，需先处理约束。
权限要求 需要DELETE权限。 通常需要更高权限（如DROP权限）。
存储空间释放 不立即释放存储空间，标记为可复用。 立即释放存储空间到数据库系统。

5. DQL优化建议
  1. 避免全表扫描
    • 对常用查询字段建立索引（如 WHERE 或 JOIN 的字段）。
  2. 减少返回列数
    • 明确指定需要的列，而非使用 SELECT *。
  3. 慎用 DISTINCT
    • 去重可能增加计算开销，优先用业务逻辑避免重复数据。
  4. 分页优化
    • 大数据分页时，避免 LIMIT N, M 深度分页，改用游标或基于索引的条件查询。

  3. 前端页面展示用户信息或商品列表。

  4. 数据分析（如用户行为、业务趋势分析）。

  5. 数据导出与清洗（筛选目标数据到文件或其他系统）。

范式

数据库设计中的三大范式（1NF，2NF，3NF）是规范数据库存储结构的核心规则，旨在消除冗余并保证数据的一致性。

1.第一范式（1NF）：原子性

  • 规则：列的属性不可再分，确保每个字段值都是原子值（单一值）。

  • 问题场景：一个字段存储多个值（如电话号码），导致查询困难。

  • 修正方法：

    • 单列拆分：将复合值拆分为多列（例如拆分“姓名”为“姓”“名”）。
    • 行拆分：将多值拆分到多行（例如电话表中一行一个号码）。
2.第二范式（2NF）：消除部分依赖
  • 规则：在满足1NF的基础上，非主键字段必须完全依赖于整个主键（非部分依赖）。
  • 问题场景：联合主键情况下，部分字段仅依赖部分主键，导致冗余。
  • 修正方法：拆表，将部分依赖的字段移到新表中。
第三范式（3NF）：消除传递依赖
  • 规则：在满足2NF基础上，非主键字段不能依赖其他非主键字段（即无传递依赖）。
  • 问题场景：非主键字段彼此依赖，导致修改时需要更新多处。
  • 修正方法：拆表，将间接依赖的字段独立。

索引

索引的概念与作用

​ 定义：帮助存储引擎快速获取数据的一种数据结构，形象的说索引就是数据的目录。

​ 核心作用：

​ 加速查询：减少全表扫描，提高 SELECT、JOIN、WHERE、ORDER BY 等操作的效率

​ 保证唯一性：唯一索引（如主键索引）可强制字段值唯一

​

  • 代价：
    • 占用存储空间：索引本身需要磁盘空间。
    • 影响写入性能：INSERT、UPDATE、DELETE 操作需维护索引，可能变慢。
常见的索引类型
(1) 按数据结构分类
索引类型 数据结构 适用场景 优缺点
B+树索引 B+树 默认索引类型，支持范围查询、排序、模糊匹配 平衡查询性能和存储，范围查询高效
哈希索引 哈希表 精确匹配（如 WHERE key = value） 查询O(1)，但无顺序性，不支范围查询
全文索引 倒排索引 文本字段的关键词搜索（如 LIKE '%keyword%'） 支持模糊匹配，但占用空间大
R树索引 R树 地理空间数据（如 GIS 坐标查询） 复杂度高，特定场景使用
(2) 按逻辑功能分类
索引类型 特性
主键索引 唯一且非空（PRIMARY KEY）
唯一索引 字段值唯一（UNIQUE KEY），允许NULL
普通索引 无唯一性约束，仅加速查询（INDEX）
复合索引 多列组合索引（如 INDEX (col1, col2)）
索引的数据结构详解
(1) B+树索引（最常用）
  • 结构特点：
    • 叶子节点：存储实际数据（或主键值 + 数据地址），通过链表连接，支持顺序遍历。
    • 非叶子节点：仅存储索引键值和子节点指针，减少树的高度。
  • 优势：
    • 范围查询高效：叶子节点链表支持范围扫描（如 WHERE id > 100）。
    • 高扇出性：每个节点可存储更多键值，3~4层即可支持千万级数据。
